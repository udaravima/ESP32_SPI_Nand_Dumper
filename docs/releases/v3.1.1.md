# ESP32 SPI NAND Dumper — v3.1.1

**Release date:** 2026-08-17
**Type:** patch — two bug fixes, no protocol or API changes.

A follow-up to v3.1.0 fixing a crash it introduced and closing a silent-corruption
gap in ECC-on dumps. Reflash the firmware; `dump.py` is unchanged.

---

## Fixes

### Boot-loop crash when WiFi fails to connect
v3.1.0 emptied the default WiFi credentials (to keep the password out of source).
The side effect: a freshly-flashed board that starts without valid credentials hit
a null-pointer dereference in the serve loop — `loop()` called into a TCP server
that was never created — and panicked/rebooted every few milliseconds.

Now the server handle is guarded, and `setup()` no longer dead-ends: if WiFi
doesn't come up, the board keeps running and prints a hint. Press **`M`**, enter
SSID/password, and it **retries the connection live** — no reset needed.

### ECC-on dumps now flag uncorrectable pages
With ECC enabled, the on-die engine corrects up to 8 bit-errors per 512-byte
sector and reports the outcome in its ECC status field (ECCS). The dumper never
read it — so a page with **more** errors than the engine could correct came back
silently, and the per-page CRC couldn't help (it's computed over whatever the chip
returns, corrected or not).

The firmware now reads ECCS after each page during an ECC-on dump and reports, in
the summary, the count of **uncorrectable** and **refresh-recommended** pages (plus
the first 20 uncorrectable page indices). Decoding follows the datasheet's ECC
status table. This is the correctness signal you want before trusting an ECC-on
image for filesystem recovery.

> Note: the signal currently prints on the **serial console**. Recording
> uncorrectable pages into a PC-side sidecar (like `badpages.json`) would require a
> wire-protocol bump to v3 and is deliberately left for a future release.

## Verification

- **Host tests:** 32 pytest passing.
- **Firmware logic:** 14 native Unity tests passing (+2 for the ECCS decoder).
- **Builds:** `esp32dev` and `esp32-s3-devkitc-1` both compile.

### Still to confirm on hardware
The WiFi-recovery flow: flash a board with no saved credentials, press **`S`** — it
should print the retry hint and keep running (not reboot) — then **`M`**, enter
credentials, and confirm it connects.
