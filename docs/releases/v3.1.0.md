# ESP32 SPI NAND Dumper — v3.1.0

**Release date:** 2026-08-17
**Theme:** integrity you can prove, settings that persist, one binary for any modern ESP32.

v3.0 made the dumper chip-agnostic. v3.1.0 makes each dump *trustworthy* and the
tool *pleasant to live with* — after a real corrupt dump (the `dump2` incident)
sailed through as a "successful" 272 MB file with no complaint.

---

## Highlights

- **Every page proves itself.** A per-page CRC32 seal (wire protocol v2) is
  re-checked on the PC; a bad page is pinned to its index in a
  `<dump>.badpages.json` sidecar instead of passing silently.
- **The tool remembers itself.** ESP32 settings persist in NVS; `dump.py` takes
  `--ip` once and remembers it. No more editing source between runs.
- **One binary, any modern ESP32.** The firmware queries its own chip model,
  cores, clock, and free memory at boot and sizes its buffers from that — no
  per-board edits.
- **Smarter repair.** `verify_dump.py` uses the CRC verdicts to rebuild a clean
  image from several dumps, preferring pages that actually passed their seal.

---

## What's new

### Integrity
- **Per-page CRC32 (proto v2).** Each page ships as `[data][CRC32]`; `dump.py`
  verifies it, always writes the bytes (so majority vote keeps them), and lists
  any failures in `<dump>.badpages.json`. Sealed end-to-end ESP→PC; `dump.py`
  still reads v1 dumps.
- **Graceful mid-dump disconnect.** The firmware detects a dropped client and
  returns cleanly to waiting instead of streaming into a dead socket.

### Persistence
- **NVS config** on the ESP32 — WiFi creds, port, clock, read mode, verify, ECC,
  retries, batch size — saved on every menu exit, reloaded on boot. Geometry stays
  auto-detected. A validation clamp guards against a corrupt NVS record.
- **`dump.py` config** — `--ip` / `--port` / `--out-dir`, remembered in a local
  (gitignored) `dump.config.json`.

### Throughput & portability
- **Runtime capability report** at boot (chip, cores, clock, heap/PSRAM, flash).
- **Batch knob `[B]`** — coalesce N page-frames per TCP write; runtime-selectable
  to benchmark, auto-clamped to available memory.
- **`dump.py` progress** now shows elapsed time + ETA and reports average MB/s.

### Tooling & docs
- **`verify_dump.py`** — CRC-aware health report and cross-dump repair.
- Hardware **write-protection** guidance (CS# pull-up; WP# tie, single-mode only).

## Upgrade notes

- **Reflash** both the firmware and pull the new `dump.py`. The wire protocol is
  now v2; a v3.1.0 `dump.py` reads both v2 and old v1 dumps, but v3.1.0 firmware
  always emits v2.
- **WiFi credentials are no longer compiled in.** On a freshly-flashed board,
  enter SSID/password once via the serial menu (`[1]`/`[2]`) and press `[S]`; they
  persist to NVS thereafter.
  - *Security note:* the previously hardcoded credentials remain in git history.
    Rotate that WiFi password to fully retire them.
- **NVS schema is v2.** A config saved by an earlier build is ignored (not
  mis-read) and defaults are used until you save again.
